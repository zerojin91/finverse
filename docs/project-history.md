# FINVERSE 프로젝트 히스토리와 방향

이 문서는 구현 세부보다 제품 의도와 누적된 주요 결정을 보존한다. 작업 전 `AGENTS.md`와 함께 읽고, 새 방향을 추가할 때는 날짜·결정·이유·영향을 남긴다.

## 제품 방향

- FINVERSE는 실제 시장 자료를 바탕으로 사용자가 금융 판단을 연습하는 이벤트 시나리오 플랫폼이다.
- 미래를 예언하는 서비스가 아니라, 과거·현재 데이터에서 근거를 만들고 불확실한 사건과 시장 참여자의 상호작용을 관찰하는 연습 도구다.
- LLM은 자료의 맥락화, 에이전트 반응, 시나리오 서술을 담당한다. 가격·사건·수익률을 확정적으로 약속하지 않는다.

## 현재 사용자 흐름

`종목 선택 → 실제 자료 준비 → 투자 상태 → 시뮬레이션 설정 → 시작 준비 → 모의 투자`

- 종목 선택 후 최근 실제 OHLC 캔들을 먼저 보여준다.
- 자료 준비 단계에서 시장·경제·사건·커뮤니티의 실제 적재 건수와 기준 시점을 보여준다.
- 캐시 응답이어도 각 단계는 최소 대기 시간을 유지해 사용자가 순차적으로 이해하도록 한다.
- 투자 상태는 명시적으로 확정해야 다음 단계가 열린다.
- 시뮬레이션 설정에서는 초기 상황이 실제 Evidence Markdown 4종을 바탕으로 World Agent의 초기 세계 상태와 시장 참여 에이전트의 초기 입력을 만든다.
- 초기 상황의 요약·종목 이벤트 시퀀스·위험 요인·관찰 포인트가 모두 표시된 뒤 시장 참여 에이전트를 공개하고 해당 위치로 이동한다. 프로필 생성 완료 뒤에는 캐시 여부와 무관하게 최소 1.5초를 지킨 뒤 시작 준비로 이동한다.
- 시작 준비 단계에서 10·20·60거래일을 최종 선택하며, 다시 설정하기는 선택 종목은 유지하고 초기 상황의 MD·분석·에이전트 프로필 캐시를 비운 뒤 투자 상태부터 재생성한다.
- `모의 투자 시작하기`를 누르면 게임 생성 직후 첫 거래일만 자동 진행한다. 이후에는 사용자가 `하루 진행` 또는 `자동 진행`을 선택하며, 첫 자동 호출 실패 시 게임을 유지한 채 수동 진행으로 재시도할 수 있다.

## 데이터와 맥락 원칙

- 데이터의 중심은 원격 AWS PostgreSQL의 `lake.records`와 동기화된 도메인 뷰다.
- 시장·경제·사건·커뮤니티 자료의 건수는 실제 DB 조회 결과이며, 이벤트와 커뮤니티는 종목별 데이터가 아닌 시장·일별 집계가 섞일 수 있으므로 UI에서 범위를 과장하지 않는다.
- 초기 상황 맥락은 선택 종목의 네 도메인 자료를 종목 타깃형 Evidence Markdown으로 먼저 만들고, 그 문서를 OpenRouter로 분석한다. 결과에는 현재 추세, 수급, 주요 이슈, 위험, 긴장 관계, 불확실성, 관찰 포인트와 문서 근거 목록을 포함한다.
- 초기 상황의 종합 분석은 네 Evidence Markdown이 모두 준비된 뒤에만 시작한다. 이 분석은 종목 전체 현황과 최근 한 달의 `종목 이벤트 시퀀스`를 함께 반환하며, 이벤트는 문서에서 확인된 실제 흐름과 문서 종합 해석을 구분해 표시한다.
- 초기 상황 최상단은 긴 문단 대신 실제 근거와 그 의미를 함께 담은 음슴체 `5줄 요약`으로 먼저 보여준다.
- 초기 맥락은 입력 데이터 지문과 스키마 버전으로 12시간 캐시하며, 시나리오 시작 시 화면에서 확인한 맥락을 게임에 저장한다.

## 에이전트·시나리오 방향

- FINVERSE는 MiroFish의 독립 에이전트·기억·라운드 모델을 차용하되, OASIS의 SNS 행동은 사용하지 않는다. 금융 주문과 리밸런싱을 위한 FINVERSE 전용 행동 라이브러리와 결정론적 체결 엔진을 사용한다.
- 초기 상황의 네 Evidence Markdown과 종합 맥락을 입력으로 개인 40·외국인 6·기관 12·연기금 1, 총 59개 프로필을 각각 생성한다. 모든 프로필은 역할·편향·신호 가중치·위험도·보유 기간·주문 한도·기억을 가진 독립 객체이며, 실행 시에도 각자 독립 LLM 판단을 한다. 설정 화면에서는 범주 카드를 눌러 개별 프로필의 관점·편향·신호·사건 반응·위험 규칙을 확인할 수 있지만, 자금·보유·개인 기억·프롬프트는 공개하지 않는다.
- World Agent는 투자자가 아닌 상태 유지형 환경 주체다. 고정 실제 근거, 일별 환경 변화, 사건·신호·시장 반응의 인과 관계를 World Memory에 append-only로 보존한다. 거래일 안에서는 외부 환경이 먼저 공개 정보를 만들고 에이전트와 사용자가 같은 공개 정보로 행동한다.
- 사건 수는 기간별로 고정하지 않는다. 모멘텀·계절성·서프라이즈 사건은 시작 시점 이전의 실제 유사 사례 retrieval을 거쳐 WorldState 조건에 따라 생성하며, 실제 근거와 가상 전개를 명확히 분리한다.
- 사용자는 10·20·60거래일과 초기 투자 상태만 설정한다. 매일과 중요한 사건에서 남긴 `매수 고려·관찰 계속·매도 고려` 판단은 사용자 판단 메모리가 되어, 최종 리포트가 수익률 외 추세 추종·성급한 반전 기대·확증 편향 등의 패턴을 분석하는 근거가 된다. World 모드의 이 판단은 주문이 아니며 가격·수급을 바꾸지 않는다.

## 작업 기록

### 2026-09-05 — 모의투자 시작 직후 첫 거래일 자동 진행

- 시나리오 생성 직후 `0/기간` 화면에 멈추지 않도록 첫 거래일 진행 작업을 한 번 자동 호출했다.
- World 모드는 `advance`, 기존 모드는 `advance_days`를 사용하고 `days: 1`만 전달해 첫날만 진행한다. 이후 진행 방식은 사용자가 선택하며, 자동 호출 실패 시 수동 `하루 진행`으로 재시도할 수 있다.

### 2026-09-05 — 하이닉스 에이전트 완료 화면 전환 경쟁 조건 수정

- 하이닉스에서 백엔드 작업 상태가 `completed`이고 프로필 59개도 준비됐지만 화면이 계속 준비 중으로 남는 문제를 확인했다.
- 완료 작업 state보다 프로필 매니페스트 state를 먼저 저장하도록 폴링 순서를 수정해 시장 참여 에이전트 카드와 `05 · 시작 준비`가 정상적으로 열린다.

### 2026-09-05 — 원격 main 변경과 모의투자 기능 통합

- 원격 `main`의 수집기·증분 PostgreSQL 적재·YouTube 커뮤니티·대시보드 변경을 기존 모의투자/World Agent 구현과 충돌 없이 병합했다.
- 병합 후 Next.js 프로덕션 빌드와 프로젝트 가상환경 기준 전체 테스트 132개를 통과했다. 시스템 Python에서의 테스트 실패는 코드 오류가 아니라 의존성 미설치(`openai`, `flask_cors`, `ddgs`, `deepagents`)였으며 `.venv`로 재검증했다.

### 2026-09-05 — 실행 차트 거래량·중복 점선 정리

- 시나리오 캔들에서 거래량 막대를 제거해 가격 흐름과 사용자 판단 마커에 집중하도록 했다.
- 시뮬레이션 시작 기준선은 최초 한 번만 표시하고, 기준선 우측 상단에 시작 라벨을 배치했다. 이후 이벤트 발생 위치에는 별도 세로 점선을 추가하지 않는다.

### 2026-09-05 — 실행 화면 차트 폭과 20봉 슬라이딩 윈도우 정리

- 실행 화면 상단의 시나리오 캔들과 투자 시뮬레이션 패널을 2:3 비율로 맞추고, 하단 시장 기록의 이벤트 기록 열도 같은 기준을 사용해 오른쪽 끝을 정렬한다.
- 시나리오 캔들은 최대 20개만 표시한다. 20개가 되기 전에는 남은 시뮬레이션 영역을 빈 슬롯으로 보여주고, 이후에는 새 캔들이 오른쪽에 추가되며 가장 오래된 캔들이 왼쪽에서 빠진다.

### 2026-09-05 — 모의투자 종료 후 사용자·시나리오 AI 보고서 분리

- 종료 시 OpenRouter를 별도 호출해 사용자의 일자별 매수·매도·관찰 판단을 평가하는 `투자보고서`와 World State 일별 변화·발생 이벤트·종목 흐름·4개 주체 및 개별 에이전트 행동을 설명하는 `시나리오 보고서`를 생성한다.
- 두 보고서는 `agent_rounds`, `daily_reflections`, 사용자 체결, `world.memory`를 입력으로 사용하며, 최종 자산·손익·수익률은 LLM 문장이 아닌 `scenario_portfolio` 검증값을 화면에 우선 표시한다.
- JSON 필수 키 검증과 두 보고서 분리 생성 회귀 테스트를 유지한다.

### 2026-09-05 — 과거 거래대금 기반 시장 참여자 대표 규모 보정

- 59개 에이전트의 독립 판단은 그대로 유지하되, 각 에이전트의 작은 가상 자본에만 `allocation_pct`를 적용하던 방식으로 인해 개인 40명의 합산 주문이 실제 종목 규모를 대표하지 못하는 문제를 수정했다.
- 게임 시작 전 선택 종목의 과거 `trading_value`를 총 거래대금 기준으로 사용하고, 종목별 `investor_flow`가 있으면 절대 순수급을 범주 구성 비중의 proxy로 삼아 개인·외국인·기관·연기금별 대표 목표 금액을 계산한다. 순수급은 총 매수·매도 금액이 아니므로 총 규모가 아니라 구성 비중에만 사용하며, 데이터가 없으면 보수적 기본 비중으로 대체한다.
- 목표 금액을 각 범주의 BUY/SELL 에이전트들에게 독립 판단의 배분 비중·확신도에 따라 나누고, 범주별 가상 원장도 필요한 대표 규모까지 확장해 현금·보유 수량 검증을 유지한다. 라운드에는 `group_notional_targets`, `group_notional_actuals`, 산정 방법·커버리지가 남아 일일 요약과 최종 회고가 같은 기록을 사용한다.

### 2026-09-05 — 거래일별 사후 시장 해설과 기본 판단 저장

- 각 거래일의 59개 독립 에이전트 체결이 끝난 뒤 개인·외국인·기관·연기금별 매수·매도·관망 집계와 가격 구성요소를 OpenRouter에 전달해 오늘의 시장 요약, 주체별 행동, 주가 변동 이유 추론을 생성하도록 했다.
- 결과는 `agent_rounds.market_summary_detail`에 저장하고 우측 `투자 시뮬레이션` 패널에서 보여준다. OpenRouter가 응답하지 않아도 거래를 중단하지 않고 집계 기반 설명을 표시한다.
- 평상시 거래일에 사용자가 판단을 누르지 않으면 `관찰 계속`을 기본값으로 날짜별 판단 원장에 저장하며, 이후 선택 시 해당 기록을 사용자 판단으로 갱신한다. 진행 버튼은 `자동 진행`·`하루 진행`으로 정리했다.

### 2026-09-05 — World 모드 중요 사건을 방향성 판단으로 단순화

- 중요 사건에서도 별도 수량·매수/매도 주문·판단 근거 입력을 제거하고, 평상시와 같은 `매수 고려·관찰 계속·매도 고려` 선택만 기록하도록 통일했다. 선택 후에는 59개 에이전트의 사건 반응과 시장 체결이 자동으로 이어진다.
- World 모드 판단은 `daily_reflections`와 `decision_log.user_stance`에 남기며, 최종 리포트는 이 기록을 시장 결과와 비교한다. 기존 시나리오 모드의 주문 입력과 서버 호환 API는 유지한다.
- 차트에는 매수·매도 판단을 보라색·주황색 마커로 표시하고, 범례도 `내 매수 판단`·`내 매도 판단`으로 구분한다. 관찰 계속은 중립 판단이므로 차트를 과밀하게 만들지 않기 위해 별도 마커를 그리지 않는다.

### 2026-09-05 — 이벤트·에이전트 거래일 기록 화면 재구성

- 하단 기록 영역을 이벤트 기록과 에이전트 활동의 2열 구조로 바꿨다. 발생한 이벤트는 누적 타임라인에서 선택해 상세 내용을 확인하고, 이벤트가 없을 때도 빈 기록 영역을 유지한다.
- 개인·외국인·기관·연기금 탭에서 agent_rounds의 거래일별 주문을 필터링하고, 각 날짜를 펼쳐 개별 에이전트의 전략·행동·수량·판단 근거를 확인할 수 있게 했다.
- 새 저장 경로를 만들지 않고 기존 revealed_events, World Memory의 event_ledger, agent_rounds를 재사용하므로 이후 보고서 분석에 필요한 기록과 화면이 같은 원장을 바라본다.

### 2026-09-05 — World Agent 사건을 선택 종목 근거로 제한

- 뉴스 레이크의 종목 태그 공백 때문에 모든 기사가 각 종목의 시장 사건으로 들어가던 경로를 수정했다.
- 이제 선택 종목명으로 확인되는 개별 기사와 한국은행·금리·환율·지수 등 명백한 시장 전체 기사만 초기 Evidence·World Agent 유사 사례 후보로 사용한다.
- 이력 캐시 스키마를 갱신해 이전에 저장된 타사 뉴스 후보는 새 시나리오에 재사용되지 않는다.

### 2026-09-05 — 거래 흐름에 이벤트 기록을 결합

- 하단 패널은 시장 반응과 이벤트 기록을 함께 보여주며, 현재 이벤트와 이미 공개된 이벤트를 누적해 이후 수급·가격 반응과 연결해 읽을 수 있게 했다.
- 시나리오 캔들의 미래 영역은 거래일별 빈 칸이 아니라 하나의 남은 기간 블록으로 표시하고, 진행된 거래일만 캔들로 전환한다.

### 2026-09-05 — 실행 헤더 간소화

- 실행 헤더는 종목·현재가·제어와 진행 상태·자산 요약의 두 층으로 나눠 정보 위계를 분명히 했다.
- 내부 에이전트 구현 설명은 제거하고, 차트의 미래 구간은 텍스트 없이 낮은 투명도의 빈 영역으로 남겨 실제 진행 캔들이 채워질 공간임을 보여준다.

### 2026-09-05 — 설정 흐름 단순화

- 설정 화면의 저장 게임 이어하기 목록을 제거해 새 연습은 항상 종목 선택부터 바로 시작한다.

### 2026-09-05 — 에이전트 완료 단계 안정화

- 59개 프로필 완료 뒤 단계 공개가 이전 비동기 효과에 의해 되돌아가지 않도록 설정 화면의 전환 값을 단조롭게 유지한다.
- 캐시된 프로필도 준비 화면 1.5초를 지킨 뒤 시작 준비 단계로 넘어간다.

### 2026-09-05 — 실행 화면 정보 밀도 조정

- 거래 단계·진행률·포트폴리오 요약을 상단 헤더의 압축 상태 바로 옮겼다.
- 차트 위의 중복 요약 블록을 제거해 시나리오 캔들과 시장 참여자 반응을 더 넓게 표시한다.

### 2026-09-05 — 매 거래일 사용자 판단 기록과 빠른 진행 추가

- 반복 설명 중심의 `오늘의 연습` 패널을 제거하고, 실제 하루가 열린 뒤 그날의 시장 요약과 `내일 매수 고려·관찰 계속·내일 매도 고려` 선택을 표시한다.
- 일일 판단은 주문과 분리돼 가격·수급에 영향을 주지 않으며, 날짜·당일 수익률·시장 요약과 함께 저장해 최종 회고가 다음 거래일 반응과 비교할 수 있게 한다.
- `하루씩 보기`는 한 거래일만 진행하고, `중요 사건 전까지 빠르게 진행`은 여러 날을 넘기되 중요한 사건의 사용자 판단 단계나 시나리오 완료에서 반드시 멈춘다.

### 2026-09-05 — PEM 터널 연결과 캔들 조회 timeout 구분

- 종목 선택 오류는 PEM SSH 터널 단절이 아니라 `lake.records` 최근 캔들 조회가 PostgreSQL statement timeout에 걸린 문제로 확인했다.
- GIN 인덱스를 더 좁게 쓰도록 종목 코드와 KOSPI 시장을 함께 조건으로 넣고, 선택 화면 캔들 조회는 45초 제한을 사용한다.
- 이후 동일 오류는 연결 실패 대신 데이터 조회 시간 초과로 표시해 사용자와 운영 점검의 원인을 분리한다.

### 2026-09-05 — 거래일 흐름이 보이는 게임 화면으로 재구성

- 시나리오 캔들은 과도한 실제 이력 대신 기간에 비례한 짧은 과거만 남기고, 10·20·60거래일 전체에 해당하는 미래 슬롯을 먼저 확보한다. 진행된 거래일만 해당 슬롯을 채우며 과거도 상승·하락 색과 낮은 투명도로 표시한다.
- 차트 하단을 `오늘의 시장 참여자 반응`으로 바꿔 집단 주문·수급 압력·그룹별 심리가 현재 캔들을 형성한다는 관계를 보여준다.
- 에이전트 반응 기록은 전체 폭으로 확장하고, 우측의 `주문 티켓`은 평상시 관찰과 중요 사건 판단을 포괄하는 `오늘의 연습` 패널로 교체했다.

### 2026-09-05 — 최초 안내에서 첫 거래일 즉시 시작

- World Agent 게임의 최초 사용 안내에서 `시작하기`를 누르면 안내창을 닫는 동시에 1거래일차 진행 작업을 호출하도록 연결했다.
- 진행 도중 사용 방법을 다시 확인한 경우에는 현재 거래일을 자동으로 넘기지 않도록 0일차·시장 진행 단계에서만 자동 실행한다.
- 사용 안내의 각 설명은 의미 단위로 줄을 나눠 좁은 화면에서도 문장이 자연스럽게 읽히도록 정리했다.

### 2026-09-05 — 로컬 DB 연결을 PEM SSH 터널로 고정

- 로컬 개발의 표준 DB 경로를 PEM SSH 터널로 명시하고, `npm run db:tunnel`이 `.env`의 SSH 키·호스트 설정으로 15432 포트를 유지하도록 추가했다.
- Flask는 통합 실행기 밖에서 단독 재시작해도 `FINVERSE_DATABASE_TUNNEL=1`이면 계정 정보는 보존하고 DB 호스트·포트만 `127.0.0.1:15432`로 전환한다.
- 이 규칙으로 맥북이 DB Tailnet에 직접 등록되지 않아도 AWS SSH 서버를 통해 원격 PostgreSQL에 접근한다.

### 2026-09-05 — World Agent·59개 독립 투자 에이전트 아키텍처 확정

- 초기 상황의 실제 Evidence Markdown 4종과 종합 분석을 `WorldState(t0)`로 승격하고, 이를 바탕으로 59개 독립 투자 에이전트 프로필을 생성하는 구조를 확정했다.
- World Agent는 거래일별 외부 환경과 사건 생명주기를 기억하며, 실제 과거 유사 사례 retrieval을 거친 모멘텀·계절성·서프라이즈 가상 사건만 공개한다. 투자 에이전트는 사건을 만들지 못하고 시장 반응을 통해 다음 거래일 환경에 간접 피드백한다.
- 고정 사건 수·연습 유형·OASIS SNS 행동은 제거 대상이다. 기간은 총 거래일만 정하고, 중요한 사건에서만 사용자 판단을 저장해 최종 인지편향 리포트에 사용한다.

### 2026-09-05 — World Agent 모의투자 구현 시작

- 초기 분석 완료 후 `agent-profiles` 백그라운드 작업이 59명 각각에 독립 OpenRouter 프로필 요청을 보내고 12시간 캐시한다. UI는 59개 생성 진행률과 확정된 4개 범주 요약을 보여준 뒤 시작 단계만 연다. 화면 재진입·개발 모드 effect 재실행 때는 완료 매니페스트를 먼저 다시 읽고, 중복 준비 요청은 기존 백그라운드 job을 재사용한다.
- `world_*` 게임은 저장소에서 별도 모드로 관리한다. World Agent가 거래일별 공개 환경과 유사 사례 기반 가상 사건을 생성하고, 중요 사건은 사용자 판단 게이트를 거쳐 59개 에이전트의 독립 행동·체결·환경 피드백 순서로 진행한다.
- 각 에이전트의 초기 기억과 거래일별 판단·체결 결과를 게임 파일에 누적한다. World 모드 최종 회고 입력에는 중요한 사건과 평상시의 방향성 판단, 시장 결과, 인지편향 관련 정량 신호를 포함하며 사용자 주문·근거·확신도 입력을 요구하지 않는다.

### 2026-09-05 — Evidence 문서 완료 후 초기 상황 종합 분석으로 분리

- 시장·경제·사건·커뮤니티 Evidence Markdown 준비와 OpenRouter 종합 분석을 별도 API 단계로 분리했다.
- 화면은 네 문서를 순차적으로 보여준 뒤 종합 분석 결과인 전체 요약, 종목 이벤트 시퀀스, 위험 요인, 관찰 포인트를 채운다.
- 종목 이벤트 시퀀스는 미래를 생성하지 않고 최근 한 달 문서의 실제 사건·지표·반응만 사용하며, 직접 관측과 문서 종합 해석을 구분한다.

### 2026-09-05 — 초기 상황·현재 맥락 분석 추가

- 선택 종목의 실제 4개 데이터 영역을 OpenRouter가 구조화된 JSON으로 요약하도록 추가했다.
- 분석 결과를 12시간 캐시하고, 화면과 생성된 게임에서 동일한 초기 맥락을 사용하도록 연결했다.
- 로컬 DB는 SSH 터널 `127.0.0.1:15432`를 통해 접근한다. 백엔드 재시작 때 터널 오버라이드가 빠지면 PostgreSQL 연결 타임아웃이 발생하므로 실행 스크립트에서 양쪽 서버에 같은 DB URL을 주입하도록 보강했다.

### 2026-09-05 — 초기 맥락을 종목 타깃 Evidence 문서 기반으로 통합

- 기존 온톨로지 파이프라인의 Evidence Markdown 계약을 모의투자 초기 맥락에도 적용했다.
- 선택 종목별로 시장·경제·사건·커뮤니티 원자료 문서를 캐시 디렉터리에 만들고, LLM은 문서를 근거로 초기 상황을 분석한다.
- 전체 온톨로지·GraphRAG 실행을 중복 호출하지 않고 동일한 데이터·문서 구조를 공유하는 1차 통합으로 구성했다. 이후 에이전트 프로필·미래 사건 생성도 이 문서와 분석 결과를 재사용한다.

### 2026-09-03 — 설정 화면 순차 공개와 에이전트 카드

- 캔들·자료 수집·투자 상태·시뮬레이션 설정을 순차적으로 공개하고, 캐시가 빨라도 최소 대기 시간을 유지했다.
- 기존 4개 연습 유형 선택 대신 시장 참여 에이전트 4개 범주 카드를 표시했다.
- 투자 상태 확정 버튼은 설정 영역과 연결된 compact action으로 정리했다.

### 2026-08-30~31 — 데이터 연결 구조 정리

- 대시보드·KOSPI·모의투자·MiroFish A2A의 데이터 접근을 `FINVERSE_DATABASE_URL` 기반 PostgreSQL 직접 조회로 통일했다.
