# FINVERSE 프로젝트 히스토리와 방향

이 문서는 구현 세부보다 제품 의도와 누적된 주요 결정을 보존한다. 작업 전 `AGENTS.md`와 함께 읽고, 새 방향을 추가할 때는 날짜·결정·이유·영향을 남긴다.

## 제품 방향

- FINVERSE는 실제 시장 자료를 바탕으로 사용자가 금융 판단을 연습하는 이벤트 시나리오 플랫폼이다.
- 미래를 예언하는 서비스가 아니라, 과거·현재 데이터에서 근거를 만들고 불확실한 사건과 시장 참여자의 상호작용을 관찰하는 연습 도구다.
- LLM은 자료의 맥락화, 에이전트 반응, 시나리오 서술을 담당한다. 가격·사건·수익률을 확정적으로 약속하지 않는다.

## 현재 사용자 흐름

`종목 선택 → 실제 자료 준비 → 투자 상태 → 시뮬레이션 설정 → 시작 준비 → 모의 투자`

- 종목 선택 후 최근 실제 OHLC 캔들을 먼저 보여준다.
- 자료 준비 단계에서 시장·경제·사건·커뮤니티의 실제 적재 건수와 기준 시점을 보여준다.
- 캐시 응답이어도 각 단계는 최소 대기 시간을 유지해 사용자가 순차적으로 이해하도록 한다.
- 투자 상태는 명시적으로 확정해야 다음 단계가 열린다.
- 시뮬레이션 설정에서는 초기 상황이 실제 Evidence Markdown 4종을 바탕으로 World Agent의 초기 세계 상태와 시장 참여 에이전트의 초기 입력을 만든다.
- 초기 상황의 요약·종목 이벤트 시퀀스·위험 요인·관찰 포인트가 모두 표시된 뒤 시장 참여 에이전트를 공개하고 해당 위치로 이동한다. 프로필 생성 완료 뒤에는 캐시 여부와 무관하게 최소 1.5초를 지킨 뒤 시작 준비로 이동한다.
- 시작 준비 단계에서 1·10·20·60거래일을 최종 선택하며, 기본값은 10거래일이다. 다시 설정하기는 선택 종목은 유지하고 초기 상황의 MD·분석·에이전트 프로필 캐시를 비운 뒤 투자 상태부터 재생성한다.
- `모의 투자 시작하기`를 누르면 게임 생성 직후 첫 거래일만 자동 진행한다. 이후에는 사용자가 `하루 진행` 또는 `자동 진행`을 선택하며, 첫 자동 호출 실패 시 게임을 유지한 채 수동 진행으로 재시도할 수 있다.

## 데이터와 맥락 원칙

- 데이터의 중심은 원격 AWS PostgreSQL의 `lake.records`와 동기화된 도메인 뷰다.
- 시장·경제·사건·커뮤니티 자료의 건수는 실제 DB 조회 결과이며, 이벤트와 커뮤니티는 종목별 데이터가 아닌 시장·일별 집계가 섞일 수 있으므로 UI에서 범위를 과장하지 않는다.
- 초기 상황 맥락은 선택 종목의 네 도메인 자료를 종목 타깃형 Evidence Markdown으로 먼저 만들고, 그 문서를 OpenRouter로 분석한다. 결과에는 현재 추세, 수급, 주요 이슈, 위험, 긴장 관계, 불확실성, 관찰 포인트와 문서 근거 목록을 포함한다.
- 초기 상황의 종합 분석은 네 Evidence Markdown이 모두 준비된 뒤에만 시작한다. 이 분석은 종목 전체 현황과 최근 한 달의 `종목 이벤트 시퀀스`를 함께 반환하며, 이벤트는 문서에서 확인된 실제 흐름과 문서 종합 해석을 구분해 표시한다.
- 초기 상황 최상단은 긴 문단 대신 실제 근거와 그 의미를 함께 담은 음슴체 `5줄 요약`으로 먼저 보여준다.
- 초기 맥락은 입력 데이터 지문과 스키마 버전으로 12시간 캐시하며, 시나리오 시작 시 화면에서 확인한 맥락을 게임에 저장한다.

## 에이전트·시나리오 방향

- FINVERSE는 MiroFish의 독립 에이전트·기억·라운드 모델을 차용하되, OASIS의 SNS 행동은 사용하지 않는다. 금융 주문과 리밸런싱을 위한 FINVERSE 전용 행동 라이브러리와 결정론적 체결 엔진을 사용한다.
- 초기 상황의 네 Evidence Markdown과 종합 맥락을 입력으로 개인 40·외국인 6·기관 12·연기금 1, 총 59개 프로필을 각각 생성한다. 모든 프로필은 역할·편향·신호 가중치·위험도·보유 기간·주문 한도·기억을 가진 독립 객체이며, 실행 시에도 각자 독립 LLM 판단을 한다. 설정 화면에서는 범주 카드를 눌러 개별 프로필의 관점·편향·신호·사건 반응·위험 규칙을 확인할 수 있지만, 자금·보유·개인 기억·프롬프트는 공개하지 않는다.
- World Agent는 투자자가 아닌 상태 유지형 환경 주체다. 고정 실제 근거, 일별 환경 변화, 사건·신호·시장 반응의 인과 관계를 World Memory에 append-only로 보존한다. 거래일 안에서는 외부 환경이 먼저 공개 정보를 만들고 에이전트와 사용자가 같은 공개 정보로 행동한다.
- 사건 수는 기간별로 고정하지 않는다. 모멘텀·계절성·서프라이즈 사건은 시작 시점 이전의 실제 유사 사례 retrieval을 거쳐 WorldState 조건에 따라 생성하며, 실제 근거와 가상 전개를 명확히 분리한다.
- 사용자는 10·20·60거래일과 초기 투자 상태만 설정한다. 매일과 중요한 사건에서 남긴 `매수 고려·관찰 계속·매도 고려` 판단은 사용자 판단 메모리가 된다. 매수·매도 고려 시 입력한 수량은 개인 paper portfolio에만 체결되고 시장 가격·수급에는 들어가지 않으며, 최종 리포트가 수익률 외 추세 추종·성급한 반전 기대·확증 편향 등의 패턴을 분석하는 근거가 된다.

## 작업 기록

### 2026-09-06 — 나의 투자 일지 간편 투자 성향 진단

- 현재 나의 투자 성향 카드에 손실 반응·투자 기간·변동성 수용·수익 추구를 묻는 5문항 선택형 진단을 추가했다. Grable·Lytton의 다차원 위험감수 성향 척도에서 다루는 요소를 학습 흐름에 맞게 간소화한 것이다.
- 결과는 안정형·안정추구형·위험중립형·적극투자형으로 바로 설명하며 브라우저에만 저장한다. 이는 모의투자 학습용 참고 정보이며, 금융상품 권유나 법정 적합성 평가는 아니다.
- 완료된 모의투자 기록이 있으면 설문 결과 아래에 별도로 `모의투자 기반 관찰`을 표시해, 자기응답 성향과 실제 연습 행동의 분석 근거가 섞이지 않게 했다.

### 2026-09-06 — World 모드 체결일과 이벤트 공개일 표시 정합성

- World 모드의 일반 거래일·이벤트 반응 주문 체결에 해당 `market_date`를 명시적으로 전달하고, 같은 날짜의 개인 계좌 스냅샷을 보존하도록 했다. 일자별 거래 기록·보고서·차트 마커는 이 체결일을 공통 기준으로 사용한다.
- 시나리오 캔들의 이벤트 공개일은 이벤트 배열 순서가 아닌 공개일과 캔들 날짜를 비교해 주황색 세로선·원 마커로 표시한다. 기존 완료 게임의 이미 누락된 체결일은 추정으로 덮어쓰지 않는다.
- 기존 World 게임은 일일 판단 원장의 동일 주문 ID에 거래일이 있을 때만 해당 체결일을 복구·저장한다. 주문 ID 연결이 없는 누락일은 추정하지 않는다.

### 2026-09-06 — 1거래일 빠른 체험 기간 추가

- 시작 준비의 기간 선택에 1거래일을 추가했다. 백엔드도 같은 값을 허용하며, 기본 선택은 기존처럼 10거래일로 유지한다.
- 후속 점검에서 World Agent 게임 생성 함수의 기간 검증이 10·20·60일로 남아 1일 시작을 거부하던 것을 1·10·20·60일로 통일했다. 기간 버튼도 네 항목이 한 줄에 표시되도록 4열 그리드로 변경했다.

### 2026-09-06 — 빠른 체험 기간을 5거래일로 조정

- 변경: 1거래일 빠른 체험을 5거래일로 교체했다. 화면 옵션·API 기간 구성·World Agent 생성 검증·오류 문구를 모두 5·10·20·60거래일로 통일했다.

### 2026-09-06 — 첫 거래일 자동 진행에 로그인 식별자가 빠짐

- 증상: 로그인한 사용자가 게임을 생성한 직후 첫 거래일 자동 진행이 `로그인이 필요합니다`로 실패했다.
- 원인: Next 모의투자 프록시가 게임 생성 `POST /scenarios`만 소유자 요청으로 분류하고, `POST /scenarios/:game_id/actions`는 인증 헤더 없이 Flask로 전달했다.
- 조치: 모든 `POST /scenarios/*` 경로에 세션 사용자 ID를 전달하도록 통일했다.
- 재발 방지: 게임 상태를 만들거나 진행·주문·보고서를 변경하는 경로는 생성 경로와 같은 소유자 인증 정책으로 관리한다.

### 2026-09-06 — 시나리오 캔들 시간축을 전체 기간에 맞춤

- 변경: 실제 이력은 최근 10거래일로 고정하고, 선택한 연습 기간 전체를 미래 슬롯으로 확보해 스크롤 없이 한 화면에 표시한다.
- 기준: 10거래일 연습은 과거 10일과 미래 10일을 같은 폭으로, 20·60거래일도 전체 슬롯을 같은 화면 폭에 비례 배치한다.

### 2026-09-06 — 시나리오 보고서의 에이전트 표현을 행동 흐름으로 변경

- 변경: 시나리오 보고서가 개별 에이전트 ID·번호 범위·개별 주문 수량과 금액을 나열하지 않도록 템플릿과 LLM 지침을 변경했다.
- 기준: 4개 수급 주체 안에서 관망·위험 축소·저가 매수·추세 추종·헤지 등의 행동 유형이 어떤 시장 신호와 이벤트에 반응해 전환됐고, 가격·수급에 어떻게 이어졌는지를 자연스러운 문단으로 설명한다.

### 2026-09-06 — 투자 일지의 실행 차트에 발생 가능 이벤트 표시

- 변경: 종목별 이벤트 시나리오 실험의 캔들 옆에 랜딩 페이지와 같은 `발생 가능 이벤트` 타임라인을 추가했다.
- 기준: 시작 시점 실제 데이터의 관찰 포인트와 활성 모멘텀만 보여주며, 아직 발생하지 않은 사건의 날짜·영향·결과는 표시하지 않는다. 조건이 강화되고 실제 유사 사례를 확인한 경우에만 World Agent가 공개 이벤트로 전환한다.
- 후속 조치: 차트 컴포넌트의 본문과 하단 칩이 각각 그리드 자식으로 배치돼 이벤트 레일이 다음 줄로 밀리던 구조를 차트 열 래퍼로 묶어 해소했다. 단일 열 전환 기준은 모바일 600px로 유지한다.

### 2026-09-06 — 완료 보고서의 시나리오 상단 요약

- 변경: 완료 보고서의 두 번째 탭 이름을 `시나리오`로 줄이고, 상단에 기간·시작/종료 기준가·World State 변화·공개 이벤트 수·시나리오 요약을 카드로 배치했다.
- 기준: 상세 이벤트·수급 행동을 읽기 전에 시나리오의 전체 경로와 검증된 실행 기준값을 한눈에 파악할 수 있어야 한다.

### 2026-09-06 — 계정별 투자 일지·시나리오 보고서 보존

- 완료 게임은 로그인한 소유자별 JSON 원장에 `llm_reports.investment`와 `llm_reports.scenario`를 함께 보존한다. `나의 투자 일지`는 이제 기존 시나리오 실행뿐 아니라 World Agent 실행도 읽어 두 보고서를 같은 투자 성향 히스토리에 표시한다.
- 투자 일지 보고서는 사용자 판단·체결·포지션·손익 맥락을, 시나리오 보고서는 사용자 정보를 제외한 World Memory·이벤트 원장·가격 경로·59개 에이전트 액션을 각각 전용 Markdown 템플릿과 지침으로 분석한다.
- 과거에 이미 생성된 짧은 보고서는 일지에서 `새 형식으로 두 보고서 다시 생성`을 눌러 같은 완료 원장으로 갱신할 수 있다. 이 요청과 조회는 모두 게임 소유자 세션을 확인한다.

### 2026-09-06 — 일지·모의투자 로그인 게이트 복원

- 나의 투자 일지, 판단해보기와 상단 로그인 버튼에 이메일·비밀번호 로그인 모달을 연결했다. 로그인에 성공하면 사용자가 누른 일지 또는 모의투자 기능으로 이어진다.
- 개인 투자 기록과 시뮬레이션 진입을 계정 세션과 연결해 사용자별 흐름을 유지한다.

### 2026-09-06 — 템플릿 기반 최종 보고서와 탭 UI 연결

- 사용자가 제공한 `template.md`와 `agent.md`를 각각 `docs/report-template.md`, `docs/report-agent.md`로 보존했다. 최종 보고서 생성 시 파일을 직접 읽어 템플릿 구조와 행동 분석 규칙을 OpenRouter 입력에 적용한다.

- 하단 기록 영역을 이벤트 기록과 에이전트 활동의 2열 구조로 바꿨다. 발생한 이벤트는 누적 타임라인에서 선택해 상세 내용을 확인하고, 이벤트가 없을 때도 빈 기록 영역을 유지한다.
- 개인·외국인·기관·연기금 탭에서 agent_rounds의 거래일별 주문을 필터링하고, 각 날짜를 펼쳐 개별 에이전트의 전략·행동·수량·판단 근거를 확인할 수 있게 했다.
- 새 저장 경로를 만들지 않고 기존 revealed_events, World Memory의 event_ledger, agent_rounds를 재사용하므로 이후 보고서 분석에 필요한 기록과 화면이 같은 원장을 바라본다.

### 2026-09-05 — 로컬 DB 연결을 PEM SSH 터널로 고정

- Flask는 통합 실행기 밖에서 단독 재시작해도 `FINVERSE_DATABASE_TUNNEL=1`이면 계정 정보는 보존하고 DB 호스트·포트만 `127.0.0.1:15432`로 전환한다.
- 이 규칙으로 맥북이 DB Tailnet에 직접 등록되지 않아도 AWS SSH 서버를 통해 원격 PostgreSQL에 접근한다.

- World Agent는 거래일별 외부 환경과 사건 생명주기를 기억하며, 실제 과거 유사 사례 retrieval을 거친 모멘텀·계절성·서프라이즈 가상 사건만 공개한다. 투자 에이전트는 사건을 만들지 못하고 시장 반응을 통해 다음 거래일 환경에 간접 피드백한다.
