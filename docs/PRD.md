## 2. 제품 정의

### 2.1 문제 — 아는 것과 하는 것의 간격

금융소비자가 실패하는 이유는 대개 **몰라서가 아니라 알면서 못 해서**다.

- 손절선을 정해두고, 막상 그 가격이 오면 물타기를 한다.
- 분산하겠다고 해놓고, 확신이 들면 한 종목에 몰아넣는다.
- 뉴스 보고는 안 산다면서, 뉴스가 뜨면 이미 주문을 넣고 있다.

백테스팅으로 좋은 전략을 짜도 실전에서는 한탕을 노리는 욕심에 자기 전략을 지키지 못한다. **책으로 공부한 지식은 현실에서 써보기 전까지 진짜 지식이 아니다.** 기존 서비스(뉴스·증권앱·금융교육·모의투자)는 정보와 원칙을 주지만, 감정이 개입되는 상황에서 그 원칙을 지킬 수 있는지 시험시키지 못한다.

이 간격은 **읽어서는 좁혀지지 않는다.** 실제로 그 상황에 놓여봐야 자기가 어디서 무너지는지 알 수 있고, 돈이 걸린 실전에서 배우면 수업료가 너무 비싸다.

### 2.2 핵심 가치 【확정 · 2026-09-06】

> **지식은 써보기 전까지 지식이 아닙니다.**
> **투자 공부는 했는데, 막상 그 순간엔 다르게 행동합니다.**
> **FINVERSE는 그 간격을 좁힙니다.**

한 문장 정의:

> **FINVERSE는 아는 대로 행동하지 못하는 지점을 찾아, 지식과 실행의 간격을 좁히는 투자 훈련 서비스입니다.**

이 문장이 대외 소개·스모크 페이지·공모전 자료의 기준점이다. 파생 표현을 쓸 때도 **수익률을 약속하지 않는다**는 축은 바꾸지 않는다.

> **v0.6~v0.7의 "파는 것은 예측값이 아니라 조건이다"는 폐기하지 않는다.** 다만 그것은 §5 시장 인사이트가 지키는 원칙이지 제품 전체의 가치 명제가 아니다. 상위에 §2.2가 있고, "조건을 판다"는 그 아래 놓인다.

### 2.3 왜 이 제품이라야 하는가

간격을 관측하려면 **결과를 모르는 상태**가 필요하다. 실전에는 그 상태가 있지만 돈이 든다. 백테스팅과 과거 리플레이에는 결과가 이미 있어서, 사람은 "나는 알고 있었다"고 착각한다(후견지명 편향). 학습이 일어나지 않는다.

FINVERSE는 그 상태를 인위적으로 만든다.

- **사건은 실제로 있었던 일이다.** 실제 데이터에서 뽑고 출처(`publisher` · `url` · `original_date`)를 남긴다.
- **그런데 결과는 정해져 있지 않다.** 가격 경로는 그때 그대로가 아니라 그 종목의 실제 수익률 분포와 59명의 수급으로 매번 새로 만들어진다. **검색해도 답이 나오지 않는다.**
- **사건 내용은 공개 전까지 감춘다.** 사용자는 선행 신호만 보고 판단을 남기고, 공개 뒤 다시 판단한다.
- **판단이 시장을 바꾸지 않는다.** 사용자의 기록은 학습 원장일 뿐 가격·수급에 영향을 주지 않는다. 그래서 "내 매수 때문에 올랐다"는 착각이 생기지 않고, 판단과 결과를 깨끗하게 대조할 수 있다.

## 3. 판단 훈련의 세 겹

```
[1] 안다      시장 인사이트 — 종목이 어떤 조건 위에 서 있는지, 그 조건이 깨지는 신호는 무엇인지
                  ↓  "그래서 나는 그때 어떻게 할 건데"
[2] 한다      모의 투자 — 결과를 모르는 채로 매일 판단을 남긴다             ★ 핵심
                  ↓
[3] 간격을 본다  나의 투자 일지 — 판단과 그다음 날의 결과를 나란히 놓고, 성향이 어떻게 변하는지 본다
```

**[2]가 제품의 핵심이다.** [1]과 [3]은 [2]를 위한 준비와 회수다. 세 겹 모두 【구현됨】이다.

## 6. 탭 2 — 나의 투자 일지 【구현됨】

v0.7의 【설계】가 화면이 됐다. **개인 신용정보·보유종목·자산을 일체 취급하지 않는다.** v0.6의 자산 트윈은 완전히 제거됐다.

| 블록 | 내용 |
| --- | --- |
| **현재 나의 투자 성향** | 최근 실행 기준 성향 유형 + 지표 + 관찰된 행동 |
| **나의 투자 성향 히스토리** | 실행마다 성향이 어떻게 바뀌었는지 시계열 |
| **종목별 이벤트 시나리오 실험** | 종목으로 묶은 실행 기록. 열면 리포트 전문 |

**저장 단위는 게임(1회 실행)이다.** `GET /games?summary=1`이 `GameSummary`를 반환하고, 프론트가 종목으로 그룹핑한다.

**히스토리가 이 탭의 값어치다.** 한 번의 진단은 낙인이지만, 세 번째 실행에서 `이벤트 추종형`이 `사전 포지셔닝형`으로 바뀌면 그건 학습의 증거다. §2.2의 "간격을 좁힌다"를 화면으로 증명하는 유일한 자리다.

> 【구현됨】 **소유자 구분이 붙었다.** 로그인 세션의 사용자 ID가 `X-Finverse-User-Id`로 페이퍼 트레이딩 엔진에 전달되고, 게임은 소유자별로 나뉜다. 이 탭과 모의 투자 시작은 로그인을 요구한다. → §7.7

## 7. 모의 투자 — World Agent 모드 【구현됨】 ★ 핵심

### 7.1 설계 원칙

**World Agent는 투자자가 아니다.** 공개 정보·사건 타이밍·시뮬레이션된 하루의 기억을 소유하는 **상태 유지형 환경 주체**다. 원칙 셋이 코드로 강제된다.

1. **에이전트 주문은 다음 날 시장 상태로만 흘러간다.** 외생 사건의 사실·내용·발생 자체는 절대 바꾸지 못한다.
2. **사용자 판단은 시장을 바꾸지 않는다.** 학습 원장이다.
3. **World Memory는 append-only다.** 사건·신호·시장 반응의 인과가 지워지지 않는다.

### 7.2 설정 흐름 — 6단계 순차 공개

```
① 종목 선택 → ② 자료 수집 → ③ 투자 상태 → ④ 초기 상황 → ⑤ 시장 참여 에이전트 → ⑥ 시작 준비
```

| 단계 | 하는 일 | 엔드포인트 |
| --- | --- | --- |
| ① **종목 선택** | 검색 후 **최근 36거래일 실제 OHLC** 미리보기. **시뮬레이션·미래 가격을 섞지 않는다** | `/securities` · `/securities/:t/candles` |
| ② **자료 수집** | 시장·경제·사건·커뮤니티 4도메인의 건수·최신 시점 확인. LLM을 쓰지 않는다. 캐시여도 **최소 1.5초 유지** | `/securities/:t/scenario-context` |
| ③ **투자 상태** | `신규 투자`는 금액, `기존 보유`는 평단·수량. **명시적 확정 버튼**을 눌러야 다음이 열린다 | — |
| ④ **초기 상황** | 종목 타깃형 **Evidence Markdown 4종**을 먼저 만들고, 넷이 다 준비된 뒤에만 종합 분석 | `/initial-context/documents` → `/initial-context` |
| ⑤ **시장 참여 에이전트** | 같은 `context_id`로 **59개 개별 프로필**을 백그라운드 생성 | `/agent-profiles/prepare` · `/agent-profiles` |
| ⑥ **시작 준비** | 10 · 20 · 60거래일 선택 후 시작 | `POST /scenarios` |

- 각 단계가 열리면 해당 섹션으로 부드럽게 스크롤한다. 순차 공개는 **단조 증가**로 갱신한다(늦게 끝난 비동기 효과가 이미 열린 단계를 되돌리지 못하게).
- `POST /scenarios`는 **59개 프로필이 준비되지 않으면 거부한다.**
- `다시 설정하기`는 선택 종목만 유지하고 초기 상황 MD·분석·프로필 캐시를 지운 뒤 ③부터 재생성한다.
- **v0.7의 연습 유형(`balanced`/`stress`/`opportunity`/`random`)은 사라졌다.** 사용자가 고르는 것은 기간과 초기 투자 상태뿐이다.

**초기 상황(④)이 UI 요약이 아니다.** World Agent의 `WorldState(t0)`이자 59개 프로필의 입력이다. 산출물은 근거와 의미를 함께 담은 **음슴체 5줄 요약** · 종목 전체 현황 · **최근 한 달 이벤트 시퀀스** · 위험 요인 · 관찰 포인트. 입력 지문 + 스키마 버전으로 **12시간 캐시**한다. 이벤트 시퀀스에는 **문서에 있는 실제 관측 흐름만** 넣고 미래 사건·가격 예측을 섞지 않는다.

### 7.3 시장 참여자 — 59 에이전트 【구현됨】

| 그룹 | 인원 | 심리 반감기 | 기본 위험회피 | 이벤트 반응 |
| --- | --- | --- | --- | --- |
| 개인 `retail` | **40** | 2.0일 | .45 | ×1.05 |
| 외국인 `foreign` | **6** | 5.0일 | .50 | ×1.0 |
| 기관 `institution` | **12** | 4.0일 | .48 | ×0.9 |
| 연기금 `pension` | **1** | 8.0일 | .62 | ×0.55 |

반감기가 성격을 만든다. 개인은 이틀이면 감정이 반으로 식고 연기금은 8일이 걸린다. 같은 뉴스에 개인이 먼저 몰리고 연기금이 마지막에 움직이는 이유다.

**프로필은 일회용 UI 카드가 아니라 지속되는 시뮬레이션 입력이다.** 에이전트마다 별도 LLM 호출로 역할·편향·신호 가중치·위험도·보유 기간·주문 한도·기억을 만들고 게임 내내 유지한다. **그룹 정책은 코드가 소유한다** — 프롬프트가 흔들려도 연기금이 데이 트레이더가 되지 않는다. 설정 화면은 범주 카드로 개별 프로필의 관점·편향·신호·반응·위험 규칙만 보여주고, **자금·보유·개인 기억·프롬프트는 공개하지 않는다.**

**주문 규모는 인원수 비례가 아니다** (`participant_sizing.py`). 선택 종목의 과거 `trading_value`를 총 거래대금 기준으로 삼고, `investor_flow`가 있으면 절대 순수급을 **구성 비중의 참고값**으로 쓴다. 순수급은 매수·매도 총액이 아니므로 총 규모가 아니라 비중 proxy로만 쓰며, 자료가 없으면 보수적 기본 비중(개인 .55 · 외국인 .20 · 기관 .20 · 연기금 .05)으로 대체하고 산정 방법·커버리지를 게임에 기록한다.

### 7.4 행동 라이브러리 【구현됨】

OASIS의 SNS 행동(게시·댓글)은 쓰지 않는다. `financial_actions.py`가 **FINVERSE 전용 금융 의도 17종**을 정의한다.

| 방향 | 의도 |
| --- | --- |
| 관망 | `HOLD` · `WAIT_FOR_CONFIRMATION` |
| 매수 | `BUILD_POSITION` · `CHASE_MOMENTUM` · `AVERAGE_DOWN` · `MACRO_ROTATE` · `SECTOR_ROTATE` · `ETF_FLOW_SYNC` |
| 매도 | `REDUCE_POSITION` · `EXIT_POSITION` · `PANIC_EXIT` · `RISK_OFF` · `FX_HEDGE` · `HEDGE_RISK` · `VOLATILITY_DELEVERAGE` |
| 조정 | `REBALANCE` · `STRATEGIC_REBALANCE` |

**LLM은 의도만 고른다.** 수량·현금·보유 한도·가격 영향은 결정론적 엔진이 소유하고, 의도마다 `max_allocation` 상한이 걸려 있다(예: `EXIT_POSITION` .08, `AVERAGE_DOWN` .035). 모델이 무엇을 뱉든 자금·보유 수량·거래 빈도·시장 영향력은 엔진이 강제 검증한다.

### 7.5 거래일 폐루프

```
환경 갱신 → 공개 정보·사건 → [중요 사건이면 사용자 판단 게이트] →
59개 에이전트 독립 판단 → 주문 체결·시장 결과 저장 → 일일 시장 요약 → 사용자 판단 기록
```

| phase | 사용자가 하는 일 |
| --- | --- |
| `world_market` | 관찰. 일일 판단을 남긴다 |
| `world_decision` | **중요 사건 앞. 내용은 비공개.** 판단 게이트 |
| `completed` | 종료 → 성향 진단 + 이중 AI 리포트 |

**일일 판단은 세 가지뿐이다** — `내일 매수 고려`(BUY_WATCH) · `관찰 계속`(HOLD_WATCH) · `내일 매도 고려`(SELL_WATCH). **수량·주문·근거·확신도를 입력하지 않는다.** 선택하지 않아도 `관찰 계속`이 기본 판단으로 원장에 저장되고, 나중에 고르면 같은 날짜 기록을 갱신한다.

> **주문을 없앤 것이 이 모드의 핵심 설계다.** 수익률 게임이 되면 사용자는 "얼마 벌었나"를 보고, 판단 훈련이 되면 "왜 그렇게 생각했나"를 본다. §2.2가 파는 것은 후자다.

**사건은 기간별로 고정하지 않는다.** World Agent가 WorldState에서 발생 조건을 평가해 모멘텀·계절성·서프라이즈 사건을 만든다. 모든 가상 사건은 **시작 시점 이전의 동일 데이터셋에서 실제 유사 사례를 retrieval한 뒤에만** 만들고, 결과에 유사 사례 식별자와 가상 여부를 남긴다. 이벤트 후보는 `security`·`market` 범위만 허용한다 — 타사 개별 뉴스는 근거로 쓰지 않는다.

**일일 시장 요약** — 59개 체결이 끝나면 네 주체별 매수·매도·관망 집계와 가격 구성요소, 공개 환경·사건을 OpenRouter에 보내 `market_summary_detail`을 만든다. LLM이 실패해도 **규칙 기반 집계 요약으로 거래를 계속한다.** 예측이 아니라 교육용 사후 해설이다.

**차트** — 실제 이력은 선택 기간에 비례한 짧은 구간만 보이고, 선택한 10·20·60거래일 전체 폭을 미래 슬롯으로 미리 확보한다. 실제 이력도 양봉·음봉 색을 유지하되 투명도로 시뮬레이션과 구분한다.

### 7.6 성향 진단과 이중 리포트 【구현됨】

**성향 4종** — 거래·판단 행동에서 도출한다.

| 유형 | 판정 |
| --- | --- |
| `이벤트 고회전형` | 회전율 > 1.5 |
| `이벤트 추종형` | 사후 추격 > 사전 거래 |
| `사전 포지셔닝형` | 사전 > 사후 |
| `이벤트 반응 관찰형` | 그 외 (기본값) |

**지표** — `world_decision_count` · `daily_reflection_count` · `daily_buy_watch_count` · `daily_sell_watch_count` · `turnover_ratio` · `total_return_pct` · `max_price_drawdown_pct` · `loss_avoidance_sell_count` · `high_confidence_trade_count` 외.

**이중 LLM 리포트** — 종료 후 OpenRouter를 두 번 호출한다.

| 리포트 | 담는 것 |
| --- | --- |
| `llm_reports.investment` | 사용자의 일자별 판단, 최종 자산·손익, 행동 패턴 |
| `llm_reports.scenario` | WorldState 일별 변화, 발생 이벤트, 종목 흐름, 4주체·개별 에이전트 행동 |

**최종 자산·손익·수익률은 엔진 검증값을 함께 저장하고 화면에서 LLM 서술보다 우선 표시한다**(`enforce_verified_report_metrics`). 결과론적 비난과 투자 권유를 금지하고, 편향은 기록에서 확인될 때만 교육적 가설로 제시한다.

**면책** — *"가상 시나리오에서의 행동을 바탕으로 한 교육용 분석이며 투자 권유가 아닙니다."*

### 7.7 계정과 게임 소유자 【구현됨 · `badb88a`】

일지가 "나의" 것이 되려면 게임에 주인이 있어야 한다. 최소 인증을 붙였다.

| 항목 | 구현 |
| --- | --- |
| 가입·로그인 | 이메일 + 비밀번호(8자 이상). `POST /api/auth/register` · `login` · `logout` · `me` |
| 비밀번호 | `scrypt` + 계정별 난수 salt. 평문·가역 암호를 저장하지 않는다 |
| 세션 | 난수 32바이트 토큰, **해시만 저장**. 쿠키는 `HttpOnly` · `SameSite=Lax` · 프로덕션에서 `Secure`, TTL 30일 |
| 저장소 | `var/auth.sqlite3` (Node `node:sqlite`). 공유 Postgres에 쓰기 계정을 새로 발급받지 않으려는 선택이다 |
| 소유자 전달 | 프록시가 세션에서 사용자를 찾아 `X-Finverse-User-Id` 헤더로 엔진에 넘긴다 |

**로그인을 요구하는 경계는 좁게 잡았다.** 게임을 만들고 읽고 쓰는 경로(`/games/*`, `POST /scenarios`)만 인증을 요구하고, 종목 조회·초기 상황·에이전트 프로필 같은 **탐색 단계는 로그인 전에도 열려 있다.** 처음 온 사람이 시장 인사이트와 설정 화면까지는 그냥 보고, 자기 기록이 생기는 순간에만 계정을 만들게 하려는 것이다.

> **한계 두 가지.** ① 저장소가 파일이라 배포 컨테이너를 다시 올리면 계정이 사라진다(→ §14 이슈 12). ② 이메일 검증·비밀번호 재설정·요청 제한이 없다. 심사 시연 범위에서는 수용하되, 실사용 전에는 셋 다 필요하다.

## 8. 도메인 모델

### 8.1 네 가지 정보 영역

| 영역 | 답하는 질문 | DB 스키마 |
| --- | --- | --- |
| **시장** | 실제로 무엇이 움직였나 | `market` |
| **경제** | 어떤 환경에 놓였나 | `economy` |
| **외부 사건** | 무슨 일이 원인이었나 | `events` |
| **사람들의 심리** | 사람들은 어떻게 반응하나 | `psychology` |

**온톨로지 4영역이 DB 스키마로 1:1 구현돼 있다.** `db/schema.sql`의 주석이 영역 번호를 그대로 달고 있다.

```
외부 사건 → 경제      경제 → 시장        시장 → 사람들의 심리
외부 사건 → 시장      사람들의 심리 → 시장
```

**심리는 시장의 결과이자 원인이다** — 유일한 양방향.

### 8.2 온톨로지가 둘이다

**A. 확정 온톨로지** `market_ontology_v1.json` 【구현됨】 — 엔터티 **20종** · 관계 **19종**. KOSPI 상장 보통주 / 거래일 단위 / paper_trading 범위. 규약: `Asia/Seoul` · `KRW` · `KRW_per_share` · `shares`. 채권·선물·옵션·ETF는 `not_found_in_current_catalog`.

> v0.6의 `DRIVES` `IMPACTS` `TRACKS` `CORRELATES_WITH` `CONSTRAINS` `TRIGGERS` 6종은 **폐기됐다.** 인과를 주장하려 했으나 방향·부호·강도를 실증할 근거가 없었다. v1은 인과를 주장하지 않고 **관측 사실의 구조**만 담는다. 인과 해석은 World Agent와 LLM으로 옮겼다.

**B. 런타임 생성 온톨로지** — MiroFish 빌더가 질문마다 Evidence에서 새로 만든다. 화면은 스키마가 올 때까지 빈 칸을 유지한다.

### 8.3 히스토리컬 원칙

- 일 단위 OHLCV, 최소 1년.
- 큰 움직임 시점의 뉴스·정책·경제·수급·심리에서 원인을 분석한다.
- ⚠️ **과거 결과를 미래의 정답으로 쓰지 않는다.** 현재 조건과의 차이를 함께 표시한다.
- **시작 시점 이후의 실제 데이터는 시뮬레이션 입력으로 읽지 않는다.**

## 9. 데이터 계약

### 9.1 `ScenarioGame` (World 모드) 【구현됨】

```ts
type ScenarioGame = {
  game_id: string; mode: "world" | "scenario";
  ticker: string; name: string;
  phase: "world_market" | "world_decision" | "completed";
  current_price: number; initial_reference_price: number; initial_equity?: number;
  current_day_index: number; simulation_days: 10 | 20 | 60;
  portfolio: { cash; quantity; average_price; market_value; equity;
               realized_pnl; unrealized_pnl; total_return_pct; mark_price };
  price_history: PricePoint[];
  history_candles?: HistoryCandle[];       // 실제 과거 캔들 (real 플래그)
  agent_rounds?: AgentRound[];             // 라운드별 판단·심리·시장압력 + market_summary_detail
  daily_reflections: DailyReflection[];    // BUY_WATCH | HOLD_WATCH | SELL_WATCH
  revealed_events?: ScenarioEvent[];       // 공개된 사건 누적
  world?: { memory: WorldMemoryEntry[]; state: WorldState };
  initial_context?: InitialContext;        // 5줄 요약·이벤트 시퀀스·위험·관찰 포인트
  participant_sizing?: ParticipantSizing;  // 산정 방법·커버리지
  llm_reports?: { investment?: LlmReport; scenario?: LlmReport };
  settings?: { fee_rate; sell_tax_rate; slippage_bps };
};
```

## 11. 안전 불변식

- **조건부로만 말한다.** 시나리오는 `조건 → 경로 → 반증 신호` 3종 세트. 카드뉴스 5장 중 **마지막 장은 반증 신호 고정**.
- **개인 신용정보·보유자산 일체 미취급.** 실계좌 연동 없음. 보유종목·포트폴리오·총자산을 입력받지도 저장하지도 않는다. 모의 투자의 금액·평단·수량은 **그 게임 안에서만 쓰이는 가상값**.
- **미리보기에 미래 가격을 섞지 않는다.** 종목 선택 화면의 36거래일 캔들은 실제 데이터만.
- **실제 근거와 가상 전개를 섞지 않는다.** UI·API 어디서도.
- **이벤트에는 출처를 남긴다.** `publisher` · `url` · `original_date`. 지어낸 이벤트 금지.
- **사용자 판단은 시장을 바꾸지 않는다.** World 모드의 판단은 학습 원장이다.
- **결정론적 계산은 LLM 밖으로.** 포트폴리오 평가, 수수료·세금, KRX 호가 틱, 주문 한도는 코드가 소유. **LLM 서술보다 엔진 검증값을 우선 표시한다.**
- **커뮤니티는 사실이 아니라 심리 관측값.**
- **빈 화면 금지.** LLM 실패 시 폴백(`fallbackEditorial`, 규칙 기반 요약, 더미 시그널).
- **비밀값 비노출.** `FINVERSE_DATABASE_URL`·`OPENROUTER_API_KEY`는 서버 전용.
- **차트 색** — 빨강 = 상승 / 파랑 = 하락.
- **상품 추천 금지** · **면책 문구 상시.**

## 12. 비기능 요구사항

### 12.1 ⚠️ 최대 리스크 — LLM 호출량이 한 자릿수 배 늘었다

에이전트가 18 → 59로 늘고 거래일마다 전원이 독립 판단을 하면서, **연습 1회의 LLM 호출이 수천 회 규모가 됐다.**

| 항목 | 호출 수 |
| --- | --- |
| Evidence 4종 + 초기 상황 종합 | 5 |
| 에이전트 프로필 생성 | **59** |
| 거래일 진행 | **59 × 거래일** |
| 일일 시장 요약 | 1 × 거래일 |
| 최종 이중 리포트 | 2 |

- 10거래일 ≈ **666회**
- 20거래일 ≈ **1,266회**
- 60거래일 ≈ **3,666회**

동시 실행은 `FINVERSE_AGENT_PROFILE_PARALLEL_COUNT`(기본 5)와 `FINVERSE_AGENT_ACTION_PARALLEL_COUNT`(기본 4)로만 제한된다. **무료 티어 일일 한도로는 60거래일 1회도 어렵다.** 코드에 이미 한도 소진 문구(`free-models-per-day`)가 있다.

**실측** — 2026-09-06 데모 서버(무료 티어 · 삼성전자 · 기본 동시 실행 수)에서 잰 값이다. 표본은 1회이므로 자릿수 감각으로만 쓴다.

| 구간 | 걸린 시간 |
| --- | --- |
| 에이전트 프로필 59개 생성 | 약 12분 |
| 거래일 1일 (에이전트 59 + 일일 요약) | 약 45초 |
| 10거래일 1회 (설정~종료) | 약 10~12분 |

프로필 생성은 **브라우저와 무관하게 서버 스레드에서 계속된다**(`ScenarioJobManager`). 탭을 닫아도 진행되고, 완료 시점에만 캐시에 들어가므로 그 전까지 조회 API는 `status: missing`을 반환한다. 시연 중 화면을 옮겨도 잃지 않지만, **끝나기 전에는 진행률을 알 수 없다**는 뜻이기도 하다.

**대응 후보** 【미확정 — §14 오픈 이슈 6】

1. **유료 키 전환** — 공모전 시연 전 필수. 무료 티어로는 심사 중 멈춘다.
2. **거래일당 전원 호출을 줄인다** — 활성 에이전트만 LLM을 태우고 나머지는 프로필 기반 규칙으로. 59명이 매일 다 말해야 하는지 재검토.
3. **프로필 캐시 적극 활용** — 12시간 캐시가 이미 있다. 같은 종목 재실행 시 59회를 아낀다.
4. **프롬프트 캐싱** — 프로필·WorldState처럼 게임 내내 고정인 콘텐츠를 프리픽스 앞에. system에 시각·UUID 금지.
5. **60거래일을 시연에서 뺀다** — 10거래일만 시연 경로로.

### 12.2 ⚠️ 프로덕션 실행이 막혀 있다

`vinext start`(빌드된 프로덕션 서버)의 정적 라우트 분류가 `/api/dashboard`·`/api/kospi`·`/api/market-indices`를 Workers 런타임에 올려 `cloudflare:sockets`를 import한다. 플레인 Node에서 `ERR_UNSUPPORTED_ESM_URL_SCHEME`로 죽고 해당 라우트가 503을 낸다. `make prod`가 `npm run dev`로 되돌려진 상태다(`75a1e47`).

**즉 지금 배포본이 없다.** 공모전 제출물에 "배포 URL"이 포함되므로 이건 일정 리스크다. → §14 오픈 이슈 5

### 12.3 성능·비용 지침

- **구조화 출력** — `Assessment`·`LlmReport`를 json_schema로 강제. 문자열 파싱 금지.
- **상한과 폴백** — 잡별 토큰 상한·타임아웃·재시도 상한. 잡이 8분을 넘기면 사용자에게 알린다.
- **비동기 잡 큐** — `ScenarioJobManager`. 같은 `context_id`의 겹친 요청은 기존 `job_id`를 반환(멱등).
- **캐시** — 초기 상황·Evidence·프로필은 입력 지문 + 스키마 버전으로 12시간.

### 12.4 엔진 제약 (MiroFish)

OASIS + Zep Cloud, **AGPL-3.0**. 비재현·토큰 폭식. 로컬 실행에 Neo4j + Ollama(`nomic-embed-text`) 필요. World Agent 경로는 원격 DB만으로 동작한다. → §14 오픈 이슈 2

## 부록 A. 용어집

- **World Agent** — 투자자가 아닌 상태 유지형 환경 주체. 공개 정보·사건 타이밍·World Memory를 소유
- **WorldState** — 특정 거래일의 환경 상태. `t0`은 초기 상황 분석에서 만들어진다
- **World Memory** — append-only 기록. 사건·신호·시장 반응의 인과를 보존
- **Evidence 문서** — 종목 타깃형 근거 마크다운 4종 (market · economy · events · community)
- **초기 상황(Initial Context)** — Evidence 4종의 종합 분석. 5줄 요약·이벤트 시퀀스·위험·관찰 포인트
- **에이전트 프로필** — 59명 각자의 역할·편향·신호 가중치·위험도·보유 기간·주문 한도·기억
- **대표 규모 산정(participant sizing)** — 소수 합성 인구가 실제 시장을 대신할 때 범주별 대표 금액을 실제 거래대금에서 계산
- **금융 행동(financial action)** — LLM이 고를 수 있는 의도 17종. 수량·현금은 엔진이 소유
